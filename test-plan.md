# Test Plan — SauceDemo

## 1. Цель тестирования
Проверить основные пользовательские сценарии интернет-магазина SauceDemo: логин, работа с каталогом, корзина, оформление заказа.

## 2. Объект тестирования
Веб-приложение SauceDemo (`https://www.saucedemo.com/`).

## 3. Scope (область тестирования)

### В scope:
- Логин всех 6 тестовых аккаунтов.
- Просмотр каталога товаров.
- Сортировка товаров.
- Корзина (добавление, удаление).
- Оформление заказа (Checkout).
- Валидация формы заказа.
- Logout.

### Вне scope:
- Регистрация нового пользователя.
- Оплата (демо-сайт её не имеет).
- Мобильная версия.
- Производительность под нагрузкой.
- Безопасность (SQL-инъекции, XSS).

## 4. Типы тестирования
- **Функциональное** — проверка работы функций.
- **UI** — проверка интерфейса.
- **Негативное** — проверка ошибок и невалидных данных.
- **Регрессионное** — перепроверка после изменений.

## 5. Тестовое окружение
- **ОС:** Windows 11
- **Браузер:** Chrome 120
- **Инструменты:** DevTools
- **Тестовые аккаунты:** `standard_user`, `locked_out_user`, `problem_user`, `performance_glitch_user`, `error_user`, `visual_user`
- **Пароль для всех:** `secret_sauce`

## 6. Критерии начала тестирования
- Приложение доступно.
- Тестовые аккаунты работают.
- Тест-кейсы готовы.

## 7. Критерии завершения тестирования
- Все тест-кейсы выполнены.
- Все найденные баги оформлены в баг-репорты.
- Критичные баги отсутствуют.

## 8. Риски
- SauceDemo — учебный сайт с заранее заложенными багами у `problem_user`, `error_user`, `visual_user`. Это известное поведение, а не дефекты.
- Демо-данные не сохраняются между сессиями.
- Изменения на сайте могут сломать существующие тест-кейсы.
